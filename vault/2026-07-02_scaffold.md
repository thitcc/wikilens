## 1. Project Overview

**Name:** `wikilens` (working title — keep it as the crate/package name)

**What it is:** A Windows desktop overlay for "wiki-heavy" games (Stardew Valley, Conan Exiles, Core Keeper, etc.). The player presses a global hotkey (**Shift+C**) while in-game; a slide-in panel appears docked to the **right edge of the screen**. The player types a natural-language question (e.g., *"best crops for winter"*). The app:

1. Searches the game's official MediaWiki via its public API.
2. Fetches the top matching pages as clean plaintext.
3. Sends the question + wiki content to an LLM (Anthropic API) with strict instructions to answer **only from the provided wiki content** (wiki = source of truth).
4. Streams the answer back into the panel, with a list of source pages (linked).

**Core UX principles:**
- Opens in < 200 ms after the hotkey. Starts hidden at app launch; lives in the system tray.
- When shown, the panel **takes keyboard focus** (the user types immediately, no click needed).
- `Esc` or Shift+C again hides the panel and focus returns to the game.
- Works over games running in **borderless/windowed** mode (document clearly that exclusive fullscreen is not supported).

**Non-goals for the scaffold (do NOT implement now, but structure code so they're easy to add later):**
- Automatic detection of the running game via foreground window title.
- Local cache of wiki pages (SQLite).
- Multi-monitor selection UI.
- DLL injection / DirectX hooks of any kind.

## 2. Tech Stack (fixed decisions — do not substitute)

| Layer | Choice | Notes |
|---|---|---|
| Shell | **Tauri v2** (latest stable) | Windows target only for now |
| Backend | **Rust** (stable toolchain, edition 2021) | |
| Frontend | **Vite + React + TypeScript** | No heavy UI framework; plain CSS |
| Global hotkey | `tauri-plugin-global-shortcut` (official v2 plugin) | |
| HTTP (Rust) | `reqwest` with `json` + `stream` features | |
| Async runtime | `tokio` (Tauri's default) | |
| Serialization | `serde`, `serde_json` | |
| LLM | Anthropic Messages API, model `claude-haiku-4-5-20251001` | Cheap/fast; streaming enabled |
| Errors | `thiserror` for library errors; commands return `Result<T, String>` | |
| Markdown rendering (frontend) | `marked` or `react-markdown` — pick one, sanitize output | |

**Secrets:** The Anthropic API key is read from the environment variable `ANTHROPIC_API_KEY` at runtime (Rust side only — the key must never reach the frontend). If missing, the `ask` command returns a clear error the UI displays with setup instructions.

## 4. Detailed Specifications

### 4.1 Window configuration (`tauri.conf.json`)

One window, labeled `overlay`:

```json
{
  "label": "overlay",
  "title": "WikiLens",
  "transparent": true,
  "decorations": false,
  "alwaysOnTop": true,
  "skipTaskbar": true,
  "visible": false,
  "shadow": false,
  "resizable": false,
  "width": 420,
  "height": 800
}
```

Also configure: `productName: "WikiLens"`, identifier `com.wikilens.app`, and CSP that allows `connect-src` only to the Tauri IPC (all HTTP happens in Rust, so the webview needs no external network access).

### 4.2 Window behavior (`window.rs`)

- `toggle_overlay(app: &AppHandle)`:
  - If visible → `hide()`.
  - If hidden → call `position_right_edge()`, then `show()`, then `set_focus()`, then emit event `overlay://shown` (frontend uses it to focus the prompt input).
- `position_right_edge(win)`:
  - Get `current_monitor()` (fallback: `primary_monitor()`).
  - Set size to `420 × monitor_height` (physical px, account for `scale_factor`).
  - Set position to `(monitor_width - 420, 0)` relative to the monitor's offset (important on multi-monitor setups: add `monitor.position()` to the coordinates).
- `hide_overlay(app)` — used by the `Esc` handler and tray.

### 4.3 Global hotkey (`hotkey.rs`)

- Register `Shift+C` **release-safe**: act on `ShortcutState::Pressed` only.
- Handler calls `window::toggle_overlay`.
- If registration fails (e.g., another app grabbed it), log a warning and show a tray tooltip/notification — do not crash.
- Add a `// TODO:` noting the shortcut should become user-configurable later.

### 4.4 Tray (`tray.rs`)

Menu items: **Show/Hide overlay** (calls toggle), separator, **Quit**. On window close request, `prevent_close()` and hide instead — the app only exits via tray Quit.

### 4.5 Wiki module

`games.rs` — static registry:

```rust
pub struct GameWiki {
    pub id: &'static str,        // "stardew"
    pub name: &'static str,      // "Stardew Valley"
    pub api_url: &'static str,   // MediaWiki api.php endpoint
    pub page_url: &'static str,  // base URL for human-readable pages
}
```

Seed with (verify these endpoints respond during Phase 5; if one fails, keep it in the list but note it in README):
- Stardew Valley → `https://stardewvalleywiki.com/mediawiki/api.php`, pages at `https://stardewvalleywiki.com/`
- Core Keeper → `https://core-keeper.fandom.com/api.php`, pages at `https://core-keeper.fandom.com/wiki/`
- Conan Exiles → `https://conanexiles.fandom.com/api.php`, pages at `https://conanexiles.fandom.com/wiki/`

`search.rs`:
- `pub async fn search(client, wiki, query, limit) -> Result<Vec<String>, AppError>`
- Call `action=query&list=search&srsearch={query}&srlimit={limit}&format=json`.
- Default `limit = 4`. Return page titles ranked as-is.
- Set a descriptive `User-Agent` header (`wikilens/0.1 (game overlay; contact: none)`) — Fandom/MediaWiki etiquette.

`fetch.rs`:
- `pub async fn fetch_pages(client, wiki, titles) -> Result<Vec<WikiPage>, AppError>` where `WikiPage { title, text, url }`.
- Call `action=query&prop=extracts&explaintext=1&exsectionformat=plain&titles={t1|t2|...}&format=json`.
- Truncate each page's text to **8,000 characters** (append `"…[truncated]"`) to bound token cost.
- Build `url` as `page_url + title.replace(' ', "_")` (URL-encode).

### 4.6 LLM module (`llm.rs`)

- `pub async fn answer_streaming(client, api_key, question, pages, on_delta) -> Result<String, AppError>`
- POST `https://api.anthropic.com/v1/messages` with headers `x-api-key`, `anthropic-version: 2023-06-01`, `content-type: application/json`, body: model `claude-haiku-4-5-20251001`, `max_tokens: 1024`, `stream: true`.
- **System prompt (use verbatim):**

  > You are a game-wiki assistant embedded in an in-game overlay. Answer the player's question using ONLY the wiki excerpts provided below. If the excerpts do not contain the answer, say so plainly and suggest what to search instead. Be concise and practical — the player is mid-game. Use short markdown: bold key items, small lists when comparing options. Do not mention that you were given excerpts; just answer. Wiki excerpts follow, each with its page title.

- User message = the excerpts (formatted as `## {title}\n{text}` blocks) followed by `Player question: {question}`.
- Parse the SSE stream; for every `content_block_delta` text delta, call `on_delta(&str)`.
- Accumulate and return the full text at the end.

### 4.7 Commands (`commands.rs`)

```rust
#[tauri::command] fn list_games() -> Vec<GameInfo>            // id + name
#[tauri::command] fn hide_overlay(app: AppHandle)
#[tauri::command] async fn ask(app: AppHandle, state: State<'_, AppState>,
                               game_id: String, question: String)
                               -> Result<AskResult, String>
```

`ask` flow:
1. Validate: non-empty question (trimmed), known `game_id`, `ANTHROPIC_API_KEY` present — each failure returns a distinct, user-readable error string.
2. Emit `ask://status` events so the UI can show progress: `"searching"` → `"reading"` → `"answering"`.
3. `search` → if zero results, return `AskResult` with an explanatory message and empty sources.
4. `fetch_pages` → `answer_streaming`, forwarding each delta via event `ask://delta` (payload: string).
5. Return `AskResult { answer: String, sources: Vec<Source { title, url }> }` (frontend uses the final value to replace the streamed buffer and render sources).

Concurrency guard: if an `ask` is already running, cancel-or-reject the new one (simplest acceptable: reject with `"A question is already in progress"`).

### 4.8 Frontend behavior

- `styles.css`: `html, body { background: transparent; }`; the panel is a full-height container with `background: rgba(18,18,24,0.92)`, `backdrop-filter: blur(12px)`, left border-radius 12px, dark theme, system font stack. Keep it visually minimal.
- `App.tsx`:
  - Loads games via `list_games` on mount; game selection persisted to `localStorage`.
  - Listens for `overlay://shown` → focus the prompt textarea and select its content.
  - Global `keydown`: `Escape` → invoke `hide_overlay`.
  - `Enter` submits, `Shift+Enter` inserts newline.
  - During an ask: disable input, show the status label from `ask://status`, append `ask://delta` chunks into the answer area (render as markdown), then render sources when the promise resolves.
  - Errors render inline in the answer area in a distinct style, never as `alert()`.
- `api.ts` centralizes all `invoke`/`listen` calls with proper TypeScript types. Components never import from `@tauri-apps/api` directly.

### 4.9 Capabilities (`capabilities/default.json`)

Grant only what's used: `core:default`, `core:window:allow-hide`, `core:window:allow-show`, `core:window:allow-set-focus`, `core:window:allow-set-position`, `core:window:allow-set-size`, `core:event:default`, `global-shortcut:allow-register`, plus whatever the tray requires. Do not grant `http` or `fs` to the webview.

4. **Conventions** —
   - All HTTP happens in Rust; the webview never gets network permissions.
   - The Anthropic key comes from `ANTHROPIC_API_KEY` env var, Rust-side only; never log it, never send it to the frontend.
   - Frontend talks to Rust only through `src/api.ts`.
   - Commands return `Result<T, String>` with user-readable messages; internal errors use `AppError` in `error.rs`.
   - Event names are namespaced: `overlay://*`, `ask://*` — list the existing ones and their payloads.
   - Adding a new game = one entry in `wiki/games.rs`, nothing else.
5. **Gotchas** —
   - `transparent: true` requires `background: transparent` on `html/body`, or you get a black rectangle.
   - Always position using monitor offset + scale factor (multi-monitor/DPI).
   - Exclusive-fullscreen games will cover the overlay — this is expected, not a bug.
   - Respect MediaWiki etiquette: keep the custom User-Agent, don't parallelize page fetches beyond what exists.
6. **Roadmap (do not implement unless asked)** — foreground-window game auto-detection, SQLite page cache, configurable hotkey, answer history.
