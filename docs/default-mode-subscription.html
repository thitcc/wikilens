WikiLens Default-mode subscription idea

Could Default mode become “$X a month and it just works”? Yes, on one condition: the master key never ships. Only a bounded, revocable secret may touch a user's machine.

An idea, not a commitment. Vault doc: vault/2026-08-04_default-mode-subscription.md; nothing here is scheduled.

The gap this fills

A packaged install has no WIKILENS_DEFAULT_* env, so Default mode is dead on arrival for a stranger. Today's answer is BYO key: paste your own provider key in Settings, use Custom mode. That stays the free tier. The subscription is for people who will pay to skip the key errand entirely.

✓Free tier, already built: Custom mode with your own key (Settings → Answers).
✓Paid tier, this idea: Default mode backed by a per-user secret you mint, meter, and can kill.
Why the key can't ride the exe

Not “maybe dangerous.” Bundling the owner key is a guaranteed leak with unbounded cost:

Everything shipped is extractable

The binary can be dumped with strings, the process memory inspected, and obfuscation only changes how long that takes. DPAPI can't help: the app must decrypt the key to use it, so the machine's user can too.

The wire gives it away anyway

The app has to send the key in an auth header to the vendor. A local proxy (mitmproxy et al.) reads it off the first request. No client-side trick survives this.

No cutoff, no revocation

One extracted key is unlimited spend on the owner's account, shared by every install. Revoking it bricks every legitimate copy at once.

Two viable shapes

Both keep the master secret server-side. They differ in where the ask traffic flows and how much you operate:

Provisioned keys (OpenRouter)Owned proxy
Hot path App → OpenRouter directly; your server never sees an ask Every ask streams through your server
You operate A webhook-scale backend (mint/revoke keys) A streaming relay you're on call for
Quota limit + limit_reset: monthly per key, enforced by OpenRouter Your own metering code and database
Revocation PATCH {disabled: true} Delete the session token
Control Coarse: cap only, no per-key model allowlist Total: per-request auth, model pinning, request shaping
Margin List-price inference plus ~5.5% credit-purchase fee Whatever your own vendor deal is
Fits when Validating that anyone pays at all Scale, or control starts mattering

Not exclusive: start with provisioned keys, and if the proxy is ever earned, it slots in behind the same wire protocol. target.rs already treats the endpoint as config, so the migration is an endpoint swap.

The provisioned-keys flow

Chips mark where each step runs. Only step 1 and step 5 involve your backend; asks never do.

1 Subscribe. Payment provider (Stripe, or a merchant-of-record like Paddle for tax handling) fires a webhook at your backend. your backend
2 Mint the key. POST /api/v1/keys/ with limit = the monthly quota in credits and limit_reset: monthly. Store the returned key hash beside the customer record; hand the runtime key to the user. your backend
3 Paste once. The key goes into WikiLens like any provider key and lands in the DPAPI store (keys.json). The Settings plumbing for “secret pasted once, stored encrypted” already exists. user
4 Ask. Default mode points at OpenRouter with that key. WikiLens already speaks the protocol: providers.rs lists OpenRouter, llm.rs streams its SSE. The one new app piece is a Default resolver that reads this key from the store instead of env (and pasting it still never switches the mode by itself). Quota renews at midnight UTC on the reset day. hot path
5 Cancel / abuse. Webhook again: PATCH {disabled: true} on the key hash. Instant, per-user, nothing else breaks. your backend
The bounded blast radius

The minted key still sits on a user's machine and can still be extracted. The difference is what extraction buys:

✓Worst case is their own quota. An extracted key spends at most that subscriber's monthly limit, money they already paid for. Annoying, never catastrophic.
✓Revocation is surgical. One PATCH kills one subscriber's key; every other install keeps working.
✓Downtime is cold-path only. If your backend dies, existing subscribers keep asking; only new signups and cancellations wait.
Costs accepted in this sketch
✓Fees: ~5.5% on credit purchases ($0.80 minimum via Stripe); inference at the providers' list prices, no markup either way. Price the subscription above expected usage plus fees.
✓No per-key model allowlist: an extracted key can burn its quota on any OpenRouter model. The cap bounds it; inside the app the model stays pinned.
✓Calendar resets: limit_reset fires at midnight UTC on calendar boundaries, not signup anniversaries. Accept the proration weirdness or prorate the first month manually.
